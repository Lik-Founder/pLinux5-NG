# PS5 Slim 13.60 investigation

Status: experimental; Linux boot has NOT been verified on the target console.

## Confirmed from source

- Byepervisor-Reborn documents support for 13.60 through elfldr.
- Upstream pLinux5-NG commit `978cfb3a1ff1dd5e6fc6e776c5aae3ed8c5770fd` selects a 13.60 vector, but the shared takeover assembly embeds 13.20-specific kernel addresses.
- `hv_defeat_1360_post_resume()` does not set the takeover assembly's required RDX continuation address or RAX stage selector.
- The resume chain writes a preliminary cookie before the hypervisor payload runs. A nonzero cookie alone does not establish NPT defeat.
- The 13.60 resume polling loop is unbounded and can request more rest-mode cycles automatically.
- A one-shot khook disarms the debug breakpoint but does not restore the original IDT gate and TSS IST slot. Restore them before installing another hook into the same scratch area.
- `0x062800000` and `0x62800000` are the same integer. The offset table's claim that they differ sixteenfold is incorrect; no address change is justified by that comment.

## Implementation sequence

1. Build a 13.60-only escape diagnostic that does not load Linux files or stage Linux into live guest RAM.
2. Poll for the exact completion cookie written by `break_hv`, with a finite timeout and no automatic rest-mode retry.
3. Restore the original resume hook after completion and record a persistent result.
4. Provide a separate stage-zero takeover entry/return diagnostic with explicit RDX and RAX, and no hypervisor or CFI patches.
5. Prevent the shared 13.20 full takeover from being used on 13.60 until firmware-correct VMMCALL handler and hypercall wrapper addresses are verified from the target.
6. Compile the actual PS5 ELF payloads in GitHub Actions, download the artifacts and inspect their ELF headers and checksums.
7. Test on the real console before describing any payload as working. Do not redistribute private console memory dumps.

## Hardware validation needed

- Target: PS5 Slim, reported firmware 13.60, elfldr at the user-provided LAN address.
- Prove one successful escape and normal return to the PS5 shell before attempting a Linux takeover.
- Resolve the 13.60 hypervisor VMMCALL dispatch target and kernel hypercall wrapper from the target's own dump; do not reuse 13.20 addresses by assumption.
- Verify all-core takeover, Linux startup, USB root filesystem and Ethernet independently.

## Ubuntu server / inference target

The upstream Ubuntu image is an Ubuntu 26.04 GNOME image with PS5-specific kernel support, not an Ubuntu Server image. Preserve the PS5 kernel and firmware. A headless configuration and llama.cpp CPU baseline are appropriate only after a verified Linux boot; Vulkan offload must be tested on the actual PS5 rather than assumed from desktop AMD/ROCm compatibility.

Current local constraints: the Mac has about 2 GiB free and no external physical disk was listed during discovery. No disk has been formatted or flashed. The official image host rejected HEAD but accepted a range GET; it reports a 2,046,295,744-byte compressed Ubuntu image. A full download and checksum verification have NOT occurred.
